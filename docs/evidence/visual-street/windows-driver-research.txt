Finding and package recommendation:
Keep the current official EXE+PCK package and portable Compatibility default for the
first native probe. Missing libEGL.dll/libGLESv2.dll/Agility DLLs is NOT by itself a
packaging error for these templates. Actual EXE code strings identify the ANGLE and
D3D12 paths, while PE imports contain no required third-party graphics DLLs.
The Windows build links ANGLE libraries statically with EGL_STATIC. ANGLE selects
D3D11 and GLES3. The EGL dynamic-library loading path is excluded when EGL_STATIC.
Do not graft random newer ANGLE DLLs or dxcompiler DLLs onto this matching engine.
Official build-only ANGLE/NIR versions/digests are recorded for reproducibility,
not required additional distributable DLLs.

D3D12 / WARP:
The engine loads system D3D12.dll and DXGI.dll. It tries an optional Agility 618
CreateDeviceFactory in .\\x86_64, then .\\; if unavailable it uses system
D3D12CreateDevice. Fresh pinned source DOES enumerate software adapters and marks
those DEVICE_TYPE_CPU. The earlier message saying they were skipped was corrected.
Whether a hosted Windows VM's software/runtime stack can complete this workload
must be measured; no missing GPU or WARP capability is inferred solely from DLL inventory.
A successful WARP/Microsoft Basic Render Driver run is software evidence, not physical
GPU acceptance. Shader/device/late functional failures stay fatal under the probe.

Windows can automatically change opengl3 to opengl3_angle when native OpenGL <3.3.
The actual driver is explicitly reported as opengl3_angle. The patch recognizes this
only when renderer remains GL Compatibility, exit is 0, no ERROR exists, the visual
completion marker exists, gameplay JSON matches and all four fresh PNGs validate.
It labels that first run clean_angle_fallback_detected, never native OpenGL passed.
Then a THIRD standalone run explicitly requests gl_compatibility/opengl3_angle on the
same freshly extracted artifact. That must independently match the requested driver
and all strict evidence. The gate can use this proven Compatibility path; it never
changes the Forward+ primary status. The initial functional/shader/late failure cannot
be repaired by another profile. Missing evidence is fatal. Mac behavior is unchanged.

The third run is conditional on a fully clean detected Windows fallback, avoiding an
unnecessary workload on systems already passing native OpenGL. Four current PNG names
include visual-street-high-rain.png; exact source-head/archive SHA/signing checks and
fresh file cleanup are retained. New fields explicitly expose native_opengl_validated,
automatic_angle_fallback_detected and explicit_angle_validated. CPU/WARP provenance and
physical_target_gpu_acceptance=false remain intact.
